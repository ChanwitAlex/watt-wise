# Watt Wise

เว็บต้นแบบเพื่อการเรียนรู้ ทำนายว่า "วันที่เลือก" ไฟมีโอกาสดับแค่ไหน (ทั่วประเทศไทย ตามพื้นที่ของผู้ใช้) และแจ้งเตือนชั่วโมงที่ควรระวัง มีสองหน้าหลักหลังล็อกอิน: **แดชบอร์ด** และ **แจ้งเตือน**

> โมเดลเทรนด้วย **ข้อมูลจำลอง** 17,520 แถว (730 วัน) ที่สร้างด้วย `ml/make_realistic_synthetic.py` ไม่ใช่สถิติไฟดับจริงของ กฟผ./กฟภ./กฟน. ผลที่ได้ไม่ใช่ความสามารถของระบบกับไฟดับจริง ต้องระบุที่มานี้ในรายงานโครงงาน

## ภาพรวมการทำงาน

```
data/raw/*.csv ──► ml/train.py (Python, รันในเครื่อง) ──► data/model_params.json   (เว็บอ่านไฟล์นี้ไฟล์เดียว)
                                                          data/model_results.json  (ผลประเมินไว้เขียนรายงาน)
                                                          data/*_scored.csv        (ผลทำนายบนข้อมูลเทรน ไว้ตรวจสอบ)
พยากรณ์อากาศ/สถิติย้อนหลัง (Open-Meteo) ──► Next.js คำนวณกับ model_params.json ──► แดชบอร์ด/แจ้งเตือน
```

เทรนแบบออฟไลน์ จึงไม่ต้องรัน Python บน Vercel เว็บส่งออกโครงสร้างต้นไม้และสัมประสิทธิ์จาก `model_params.json` ไปคำนวณกับอากาศของพื้นที่ผู้ใช้ ผลประเมินโมเดลทั้งหมดอยู่ใน `data/model_results.json` (ไม่มีหน้าเว็บแสดงแล้ว)

## หน้าแดชบอร์ดและหน้าแจ้งเตือน

**แดชบอร์ด (`/dashboard`)** เลือกวันที่ใดก็ได้ตั้งแต่วันนี้ถึง 5 ปีข้างหน้า (หรือกดทางลัด พรุ่งนี้/อีก 1 เดือน/อีก 1 ปี) แล้วได้คำตอบ "ไฟมีโอกาสดับไหม" เป็นระดับ ต่ำ/เฝ้าระวัง/สูง พร้อมที่มาของคำตอบ โดยแบ่งตามระยะเวลา

| ช่วง | ใช้อะไร | หมายเหตุ |
|---|---|---|
| วันนี้ถึง 16 วัน | พยากรณ์อากาศจริงรายชั่วโมง (Open-Meteo) คำนวณกับกฎสภาพอากาศและ Decision Tree | หลังวันที่ ~7 พยากรณ์อากาศแม่นน้อย หน้าเว็บบอกไว้ |
| ไกลกว่า 16 วัน ถึง 5 ปี | สถิติอากาศรายชั่วโมงของ ±7 วันรอบวันเดียวกัน ย้อนหลัง 10 ปี รันกฎ/โมเดลกับทุกวันเทียบเคียง | **บอกไม่ได้ว่าวันนั้นไฟจะดับหรือไม่** บอกได้เป็นสัดส่วนวันเทียบเคียงที่อากาศแรงถึงเกณฑ์เตือน เกณฑ์แปลงเป็นระดับ (5%/20%) เป็นค่าที่ตั้งเอง |

มุมมองผู้ดูแลอาคารเพิ่มกราฟลม/ฝน คาดการณ์การใช้ไฟรายชั่วโมง และแผนที่ความร้อนรอบตัว (จุดของคุณ + 4 ทิศ ห่าง ~28 กม. ใช้ดัชนีจากพยากรณ์จริง) ส่วนผู้ใช้ทั่วไปเห็นคำตอบ การ์ดสรุป และชั่วโมงที่ควรระวัง

**แจ้งเตือน (`/alerts`)** รายการชั่วโมงใน 16 วันข้างหน้าที่ดัชนีสภาพอากาศ (≈ ลม/120 + ฝน/80) ≥ 0.35 เรียงจากใกล้สุด พร้อมข้อความแนะนำและปุ่ม "รับทราบ" (จำในเบราว์เซอร์นั้น) ข้อความทั้งหมดเป็นกฎ ไม่ได้มาจากโมเดล

ข้อควรรู้: ในการทดสอบกับข้อมูลสังเคราะห์ Decision Tree ยังไม่ดีกว่ากฎสภาพอากาศ (ดูตารางผลด้านล่าง) ระดับคำตอบในโหมดพยากรณ์จึงใช้ระดับที่สูงกว่าระหว่างกฎกับโมเดล พยากรณ์อากาศและสถิติย้อนหลังแคชไว้ (30 นาที และ 1 วัน) ดึงข้อมูลย้อนหลังทีละ 3 ปี และลองซ้ำอัตโนมัติเมื่อล้ม (เช่น ถูกจำกัดอัตราเรียก 429) ถ้าได้ไม่ครบ 10 ปีหน้าจะบอกว่าใช้กี่ปี (ต้องได้อย่างน้อย 5 ปี) ถ้าดึงไม่สำเร็จเลยจะแสดงข้อความและปุ่มลองใหม่ ไม่ล่ม ผมทดสอบการดึงข้อมูลกับเซิร์ฟเวอร์จำลองที่ตอบรูปแบบเดียวกับ Open-Meteo เท่านั้น ก่อน deploy ให้ลอง `python ml/fetch_weather.py --start 2026-01-01 --end 2026-01-01 --check` และเปิดแดชบอร์ดในเครื่องเพื่อยืนยันกับ API จริง

พยากรณ์อากาศใช้ Open-Meteo (ไม่ต้องใช้ API key, CC BY 4.0, ฟรีเฉพาะงานไม่ใช่เชิงพาณิชย์ ต้องให้เครดิต ซึ่งหน้าเว็บแสดงไว้แล้ว) ตั้ง `WEATHER_API_URL` / `ARCHIVE_API_URL` ใน `.env.local` ได้ถ้าต้องการชี้ไปที่อื่น

## รันในเครื่อง

```bash
npm install
cp .env.example .env.local      # แล้วใส่ SESSION_SECRET (openssl rand -base64 32)
npm run dev                     # เปิด http://localhost:3000
npm run lint && npm test && npm run build
```

ถ้าเว้น `DATABASE_URL` ตอนรันในเครื่อง บัญชีผู้ใช้จะถูกเก็บในไฟล์ `data/.users.json` (ไม่ถูก commit) ใช้ได้เฉพาะตอนพัฒนา

## เทรนโมเดลใหม่

```bash
pip install -r ml/requirements.txt
npm run make-synthetic          # สร้างข้อมูลจำลองใหม่ (เปลี่ยนได้: python ml/make_realistic_synthetic.py --days 1095 --seed 7 --rate 0.03)
npm run train                   # = python ml/train.py --outage outage_sim_th.csv --usage usage_sim_th.csv --synthetic
```

random_state คงที่ (42) รันซ้ำแล้วได้ผลเท่าเดิม โปรโตคอลคือแบ่งตามเวลา 70/30 (ฝึก 12,264 แถว ทดสอบ 5,256 แถว) เลือกพารามิเตอร์ด้วย TimeSeriesSplit บนชุดฝึกเท่านั้น และไม่ปรับเกณฑ์จากชุดทดสอบ เกณฑ์เตือน 0.35 ใน `ml/train.py` ต้องตรงกับ `lib/config/risk.ts`

## ทั่วประเทศไทย: ตรวจตำแหน่งแล้วดูพื้นที่นั้น

- แถบ "พื้นที่" บนทุกหน้า: ปุ่ม "ใช้ตำแหน่งปัจจุบัน" (เบราว์เซอร์ขออนุญาตก่อน) หรือเลือกจาก 77 จังหวัด
- ลำดับที่ใช้: ตำแหน่งที่ผู้ใช้เลือก → ตำแหน่งโดยประมาณจาก IP (ใช้ได้บน Vercel ผ่านหัว `x-vercel-ip-*` เฉพาะผู้ใช้ในไทย) → ค่าเริ่มต้น กรุงเทพมหานคร
- ตำแหน่งเก็บในคุกกี้ของผู้ใช้ ปัดเศษ ~1 กม. ไม่บันทึกลงฐานข้อมูล และตรวจซ้ำทุกครั้งว่าอยู่ในไทย (คุกกี้ที่ถูกแก้จะถูกทิ้ง)
- หน้าพยากรณ์ดึงอากาศของพิกัดนั้น + อีก 4 ทิศ (ห่าง ~28 กม.) ทำแผนที่ความร้อนรอบตัว
- พิกัด 77 จังหวัดเป็นค่าโดยประมาณของตัวเมือง (`lib/config/provinces.json`)
- **ข้อจำกัดสำคัญ:** พยากรณ์อากาศเปลี่ยนตามพื้นที่จริง แต่โมเดลไฟดับ/การใช้ไฟยังเป็นชุดเดียวที่ฝึกจากข้อมูลตัวอย่าง จึงใช้กฎเดียวกันทุกจังหวัด จะปรับตามภูมิภาคได้ต่อเมื่อมีข้อมูลไฟดับจริงของภูมิภาคนั้น (ถ้าชุดข้อมูลมีคอลัมน์ `province` เว็บจะกรองตามจังหวัดที่ใกล้ที่สุดให้เอง)

## ข้อมูลที่ใช้เทรน (ข้อมูลจำลอง 17,520 แถว)

`ml/make_realistic_synthetic.py` สร้างข้อมูลรายชั่วโมง 2 ปี (ต.ค. 2024 - ก.ย. 2026) ตามโครงสร้างที่ผู้เขียนตั้งขึ้น: อุณหภูมิตามฤดู (ร้อน/ฝน/หนาว) พายุฝนช่วงบ่าย-เย็นมีลมกระโชกนำหน้า ไฟดับระดับพื้นที่ที่ขึ้นกับลมกระโชก ฝน ฟ้าผ่า โหลดกริดช่วงเย็น และสาเหตุพื้นฐานที่ไม่เกี่ยวกับอากาศ (ไฟดับ ~2.2% ของชั่วโมง) ระยะเวลาไฟดับแบบ log-normal (มัธยฐาน ~41 นาที) และการใช้ไฟครัวเรือน (~20 kWh/วัน) ไฟล์ที่ได้คือ `data/raw/outage_sim_th.csv` และ `usage_sim_th.csv`

ชุดเก่า (`make_synthetic.py` ขยายจากตัวอย่าง 720 แถว) ยังอยู่ใช้เทียบได้ เมื่อมีบันทึกไฟดับจริงให้ใช้ `ml/build_real_dataset.py` แล้วเทรนโดยไม่ใส่ `--synthetic` ข้อความเตือนบนเว็บจะเปลี่ยนเอง

## ไฟล์โมเดล (model.pkl)

`python ml/train.py ...` เขียน `data/model.pkl` (joblib) มีโมเดล 4 ตัว: `outage_tree` (โอกาสไฟดับ), `outage_duration` (ระยะเวลา นาที), `usage_mlp`, `high_usage_tree` พร้อมรายชื่อฟีเจอร์ของแต่ละตัว

```python
import joblib, pandas as pd
b = joblib.load("data/model.pkl")
m = b["models"]["outage_tree"]
x = pd.DataFrame([{"hour": 17, "is_weekend": 0, "wind_speed_kmh": 35, "rainfall_mm": 8, "wind_gust_kmh": 65}])[m["features"]]
print(m["model"].predict_proba(x)[0, 1])
```

โหลดด้วย scikit-learn เวอร์ชันเดียวกับที่เทรน (ดู `sklearn_version` ในไฟล์) เว็บไม่ได้ใช้ไฟล์นี้ เว็บอ่าน `model_params.json`
